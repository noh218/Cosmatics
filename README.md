# متجر مع تتبع فيسبوك (Pixel + Conversions API)

## التشغيل
1. ثبّت Node.js 18 أو أحدث.
2. انسخ `.env.example` إلى `.env` واملأ القيم (أو ضعها كمتغيرات بيئة في الاستضافة).
3. `npm install` ثم `npm start`.
4. افتح `/admin` وادخل بكلمة السر لإضافة المنتجات.

لو استخدمت ملف `.env` محليًا شغّل: `node --env-file=.env server.js`

## ربط فيسبوك
1. Events Manager ← Data Sources ← Pixel الخاص بك. انسخ **Pixel ID** إلى `PIXEL_ID`.
2. Settings ← Conversions API ← Generate access token. انسخه إلى `CAPI_TOKEN`.
3. للاختبار: Test Events ← انسخ الكود إلى `TEST_EVENT_CODE`، ثم افتح صفحة منتج واطلب طلبًا تجريبيًا.
   يجب أن ترى الأحداث بمصدرين: Browser و Server، وتحت كل حدث كلمة Deduplicated.
4. احذف `TEST_EVENT_CODE` بعد الاختبار.
5. في الحملة اختر هدف المبيعات (Sales) وحدث التحسين Purchase.

## Pixel خاص لكل منتج
- في لوحة التحكم، عند إضافة أو تعديل منتج، ضع **Pixel ID** و**Conversions API Token** الخاصين به (وTest Event Code عند الاختبار).
- كل حدث للمنتج (مشاهدة، بدء الشراء، الطلب) يذهب إلى Pixel هذا المنتج فقط، ولا يصل لباقي المنتجات.
- لو تركت الحقول فارغة يستخدم المنتج الـ Pixel العام من `.env`، وهو اختياري.
- الـ Token سري: لا يظهر للزوار ويراه المالك فقط بعد تسجيل الدخول.
- الصفحة الرئيسية للمتجر تستخدم الـ Pixel العام فقط إن وُجد.

## الأحداث المرسلة
- PageView و ViewContent: عند فتح صفحة المنتج.
- InitiateCheckout: عند الضغط على «اطلب الآن» أو بدء كتابة البيانات.
- Purchase (أو Lead من `ORDER_EVENT`): عند تأكيد الطلب، مع القيمة والعملة ومعرّف المنتج.
- بيانات العميل (هاتف، اسم، مدينة، دولة) تُرسل مشفّرة SHA-256 مع fbp وfbc وIP وUserAgent لرفع جودة المطابقة.
- تصفح المالك بعد تسجيل الدخول لا يُحسب.

## الاستضافة
- يحتاج استضافة تشغّل Node.js: Railway أو Render (مع قرص دائم) أو VPS.
- اضبط `DATA_DIR` على مسار قرص دائم، وإلا تضيع المنتجات والطلبات عند إعادة التشغيل.
- يجب أن يعمل الموقع على HTTPS (ضروري لكوكي الدخول ولفيسبوك).
- النسخ الاحتياطي: انسخ مجلد `data` (فيه products.json وorders.json والصور).
